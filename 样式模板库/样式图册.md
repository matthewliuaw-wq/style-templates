# 样式图册 · style-templates

公众号内容生产的样式选型总览。**样式是资产,主题随填,渲染形态按需选。**
内容怎么写(导读/解读文章的结构)见同目录 `文章导读模板包.md`。

## 三层模型

```
样式(视觉系统) × 渲染形态(交付载体) × 主题(填充内容)

同一个主题,可以换样式;同一套样式,可以换渲染形态。
```

## 两种驱动方式

**脚本驱动(01/02)**:内容写在源文件(md 或 HTML)里,跑生成脚本出交付物。适合结构性强的常规产出,改字成本最低。

**手工填充(03/04/05)**:直接在设计源里替换文字与图,再用 `出全页图.py` 截成整页 PNG。适合视觉优先的一次性精品,改字成本低、改布局成本高。

## 公共工具

- **出全页图**(03/04/05 共用):
  ```bash
  python3 出全页图.py <源.html|.svg> <输出.png> [宽度]
  ```
  Chrome 超高窗截图 + PIL 自动裁底,支持最高 16000px。首次使用先装依赖:`pip3 install Pillow markdown premailer`。

- **公众号内联**(01/02 各自目录里有生成脚本):后台只认 inline style,凡走 HTML 形态必须过内联管道。

## 硬约束备忘

- 完整适配策略(直贴 HTML / 整图 / 动图-交互 SVG 三路决策、编辑器潜规则、各样式的推荐进法)见同目录 `公众号适配指南.md`
- 公众号后台 strip `<style>`/`class`/`@font-face`,只认元素 `style=""`
- 全页 PNG 形态无样式约束(它就是一张图),但文字不可复制、不可放链接、改动需重新出图
- 微信单图 ≤10M;超长全页图建议 ≤5M、>16000px 拆分
- 图片均为相对路径,HTML 形态贴后台后逐张手动上传

## 扩展规范

新增一套样式时:

1. 建目录 `NN-样式名/`,内含:源文件(模板示例)+ `使用说明.md`(含设计系统摘要与区块地图)+ `成品参照.png`
2. 使用说明必须写清:驱动方式、渲染命令、换内容的边界(什么便宜什么贵)
3. 在本图册选型表登记一行;有新验证的渲染形态,在使用说明里追加验证记录
4. 本库即 `style-templates` 仓库本体;改完直接 commit + push,使用方 pull 即得最新
